# AGENTS.md

Technical notes for coding agents working in this repository. Human-oriented
docs: `backend/README.md`, `docs/frontend.md`.

## Repository layout

| Path | Content |
|---|---|
| `backend/` | FastAPI + SQLModel API (Python 3.15, managed with uv), Alembic migrations, pytest suite |
| `frontend/` | Vite + React SPA (TanStack Router/Query), served by nginx in production |
| `scripts/` | Standalone helper scripts (e.g. `amex_import.py`), shipped as their own image |
| `docs/` | Additional documentation |
| `clone_db.sh` | Dumps the production DB (needs 1Password CLI + LAN access) into a local Postgres on port 5433 |
| `.github/workflows/` | CI (see below) |

## Prerequisites

- Python 3.15 and [uv](https://docs.astral.sh/uv/) 0.13.x (CI pins `0.13.8`)
- Node 26 and npm (version from `frontend/package.json` → `packageManager`)
- Docker (running) — the backend tests start PostgreSQL via testcontainers

## Backend

Run everything from `backend/`.

```sh
uv sync --locked                 # create .venv incl. dev dependencies
uv run --locked ruff format .    # format (CI runs `ruff format --check .`)
uv run --locked ruff check .     # lint
uv run --locked mypy .           # type check (includes tests and migrations)
uv run --locked pytest -q        # tests; needs Docker
uv run --locked pytest tests/inbound/test_account_routes.py -q   # single file
```

CI (`backend-checks.yml`) runs `ruff format --check`, `ruff check`, `mypy` and `pytest`; all must pass.

Tests:

- `tests/conftest.py` starts one `postgres:15-alpine` container per session,
  bound to host port **5434**. Make sure that port is free.
- Tables are created from `SQLModel.metadata` (not via Alembic) and dropped/recreated per test.
- External services (Actual, Quiltt, exchange rates, LLM/PDF statement matching)
  are replaced by mocks in `tests/mockclients/` via FastAPI dependency overrides.
  Never call real external APIs from tests.
- Test layout mirrors the code layers: `tests/inbound` (HTTP routes via
  `TestClient`), `tests/business`, `tests/dataaccess`, `tests/adapter`.

Running the API locally:

```sh
# Postgres on :5433, e.g. from clone_db.sh or:
docker run --rm -d -e POSTGRES_PASSWORD=postgres -p 5433:5432 postgres
POSTGRES_PORT=5433 POSTGRES_DATABASE=postgres OVERWRITE_USER_HEADER=<username> uv run fastapi dev main.py
```

- Configuration comes from environment variables, see `config.py` (pydantic-settings;
  `POSTGRES_*`, `PLAID_*`, `ACTUAL_*`, `STATEMENT_MATCH_*`, …).
- Auth: the user is taken from a Bearer JWT (`preferred_username`) or the
  `X-Auth-Request-Preferred-Username` header set by oauth2-proxy.
  `OVERWRITE_USER_HEADER` bypasses this locally. The user must exist in the `user` table.
- Alembic migrations run automatically on startup (`main.py` lifespan).

Code structure — each domain package (`core`, `data_import`, `data_export`,
`dates`, `exchangerate`, `statement_match`) follows the same layering:

- `inbound/` — FastAPI routers
- `business/` — services / domain logic
- `dataaccess/` — repositories (SQLModel queries)
- `adapter/` — clients for external systems
- `facade.py` — the entry point other packages use; import another package through
  its facade rather than its internals (a few legacy exceptions exist)

Shared table models live in `models.py`. `data_export/adapter/openapi/` is generated code.

Migrations:

```sh
# alembic.ini points at postgresql://postgres:postgres@localhost:5433/postgres
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "short description"
```

Review autogenerated migrations by hand and commit them in `migrations/versions/`.

Dependencies: edit `pyproject.toml` (versions are pinned with `==`), run `uv lock`,
commit both `pyproject.toml` and `uv.lock`.

## Frontend

Run everything from `frontend/`.

```sh
npm ci
npm run dev        # http://localhost:3000, proxies /api to http://127.0.0.1:8000 (override with BACKEND_URL)
npm run lint       # oxlint (type-aware, incl. React hooks rules)
npm test           # Vitest (jsdom + Testing Library)
npm run build      # vite build + tsgo type check
npm run typecheck  # tsgo --noEmit only
npm run format     # oxfmt (no semicolons, 80 cols, sorts imports)
npm run format:check
npm run fix        # format + lint autofixes
```

CI (`frontend-checks.yml`) runs `npm ci`, `npm run format:check`, `npm run lint`, `npm test`, `npm run build`.

- Tests sit next to the code as `*.test.ts(x)`; setup in `src/test/setup.ts`.
- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin — don't edit it by hand.
- Use the `@/` alias for imports from `src/`.
- Conventions (amounts in integer cents, server state only in TanStack Query, …)
  are documented in `docs/frontend.md` — read it before larger changes.

## CI/CD

| Workflow | Trigger | What it does |
|---|---|---|
| `backend-checks.yml` | every PR, called by build | ruff format/lint, mypy, pytest — **required status check** "Backend checks" |
| `frontend-checks.yml` | every PR, called by build | format, lint, test, build — **required status check** "Frontend checks" |
| `backend-build.yml`, `frontend-build.yml`, `scripts-build.yml` | push to `main` and PRs touching the component | build the Docker image via `docker-image.yml` |
| `docker-image.yml` | reusable | builds, scans with Grype, pushes to `ghcr.io/antoncuranz/money-tracking/<image>` |
| `lint.yml` | every PR, push to `main` | actionlint + zizmor (workflows), hadolint (Dockerfiles) |
| `image-cleanup.yml` | weekly, manual (dry-run by default) | deletes untagged and old `pr-*`/`sha-*` images from GHCR |

Image tags:

- push to `main`: `latest`, `sha-<short sha>` (on `main`, checks must pass first)
- pull request: `sha-<short PR head sha>`, `pr-<number>` — never `latest`.
  PRs from forks build but don't push.
- The Grype scan fails the build (nothing is pushed) on **critical vulnerabilities
  that have a fix**. Usually the fix is a base image update or an OS package
  upgrade in the Dockerfile (the frontend image runs `apk upgrade` for this reason).

Workflow conventions (enforced by actionlint/zizmor):

- Pin third-party actions to a full commit SHA with the version as a comment
  (`uses: owner/action@<sha> # vX.Y.Z`); Renovate updates both.
- `actions/checkout` with `persist-credentials: false`.
- Don't interpolate `${{ … }}` directly in `run:` scripts; pass values via `env:`.
- Least-privilege `permissions:` per workflow/job.

Lint locally (Docker): `docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint`,
`uvx zizmor .github/workflows`, `docker run --rm -i hadolint/hadolint < backend/Dockerfile`.

Renovate (`renovate.json`) keeps dependencies up to date and automerges minor updates
once checks pass.

## Before you finish a change

- Backend touched → `ruff format`, then ruff check, mypy, pytest pass.
- Frontend touched → `npm run format`, then `npm run lint`, `npm test`, `npm run build` pass.
- Workflows or Dockerfiles touched → actionlint, zizmor, hadolint pass.
- Model changed → add an Alembic migration.
- Dependency changed → lockfile (`uv.lock` / `package-lock.json`) updated and committed.
